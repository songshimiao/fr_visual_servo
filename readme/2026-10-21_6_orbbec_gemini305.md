# Orbbec Gemini 305 接入、双相机选择与 Jetson 环境记录

记录日期：2026-10-21。项目目录：`/home/jetson/fairino_ws/fr_visual_servo`。

## 功能与实现

保留 RealSense D435，新增 Orbbec Gemini 305。相机原始网页预览、ChArUco 内参采集、
手眼采集、ArUco 检测、PBVS 和悬停入口使用共用彩色采集接口。
所有相机入口不指定 `--camera` 时，在**启动终端**选择：

```text
选择相机：
  1. Intel RealSense D435
  2. Orbbec Gemini 305
请输入 1/2（q 退出）:
```

选择发生在主线程、连接机械臂和启动视觉线程之前。无终端交互的运行方式必须显式传入
`--camera realsense` 或 `--camera orbbec`，不会自动猜测设备。两台设备可同时连接，
同一台设备不能同时被多个程序占用；多台 Gemini 305 时须用 `--camera-serial` 指定。
网页服务、s/q 键和采集按钮沿用原有实现。

本工程继续只开**彩色流**，不增加深度、点云、对齐处理或 ROS 依赖。
ArUco 的位置由彩色内参 + 标记实际尺寸 + PnP 计算，长度单位仍为米，
相机光学坐标仍为 x 向右、y 向下、z 向前。

`camera_stream.py` 延迟导入所选厂商 SDK。Orbbec 枚举设备与彩色流配置，优先 BGR/RGB，
同时支持 MJPG、YUYV、UYVY、NV12、NV21 和 I420 转成 BGR。
返回独立图像副本，避免 SDK 释放帧后引用失效。配置不支持时列出可用彩色流，
不自动换分辨率、不缩放图像。彩色流连续无有效帧超过 5 秒报错，退出时停止 pipeline；
PBVS 沿用视觉线程异常通知主线程退出的行为。

### 怎样配置的 / 如何复现

在 Jetson 项目根目录执行：

```bash
cd /home/jetson/fairino_ws/fr_visual_servo
bash scripts/setup_orbbec_jetson.sh
```

脚本先检查 Linux ARM64、Python 和已有 OpenCV ArUco，再执行：

```bash
python3 -m pip install --user --no-deps --only-binary=:all: pyorbbecsdk2==2.1.2
```

`--no-deps` 是有意设置的：该包的完整依赖列表包括桌面示例、点云、视频等依赖；
本工程彩色采集只需 SDK 和已有 NumPy/OpenCV。这样避免 pip 替换已经测试的
OpenCV、NumPy，也不需要安装 Open3D、pygame、pynput 或整套示例依赖。
未升级 JetPack、系统软件包或相机固件，也未更换 RealSense 驱动。
如果以后运行 SDK 自带的其他示例，应另外满足那些示例的依赖。

脚本还将 wheel 自带的官方规则安装到：

```text
/etc/udev/rules.d/99-obsensor-libusb.rules
```

然后执行 `sudo udevadm control --reload-rules` 和
`sudo udevadm trigger --subsystem-match=usb --attr-match=idVendor=2bc5`，
只触发 Orbbec USB 设备规则。规则修改需要在终端输入 sudo 密码，密码不写入工程。
如目标规则已存在且内容不同，脚本先备份为 `.backup.<时间>`。
官方规则为相机设备设置 USB 访问权限，可让普通用户运行采集程序。
USB 枚举但打开失败时，先确认规则和重新插拔 USB 3 线缆，不必使用 sudo 运行整个应用。

脚本最后实际导入两个厂商 SDK，打印版本并枚举 Orbbec 相机。
使用其他 Python 环境时可以运行 `CAMERA_PYTHON=/path/to/python bash scripts/setup_orbbec_jetson.sh`；
在 venv 内不使用 `--user`。当前实测的是上述系统 Python 3.10 环境。

官方依据：
[Orbbec SDK v2 设备支持表](https://github.com/orbbec/OrbbecSDK_v2)、
[Python SDK v2 安装文档](https://orbbec.github.io/pyorbbecsdk/source/2_installation/install_the_package.html)、
[官方 Python SDK 仓库](https://github.com/orbbec/pyorbbecsdk/tree/v2-main)、
[本次固定的 Python 包版本](https://pypi.org/project/pyorbbecsdk2/2.1.2/)。
Gemini 305 使用 SDK v2；不要安装只支持其他型号的旧 SDK v1 来替代。

## 直接运行

以下命令在项目根目录执行。浏览器访问 **http://192.168.66.80:8080/**。

```bash
# 原始彩色采集网页：终端选择相机，不连接机械臂
python3 scripts/camera_preview.py

# ArUco 检测：终端选择相机；边长换成实际值（米）
python3 scripts/algorithm/aruco_detector.py --marker-length 0.05

# 跳过菜单直接使用 Gemini
python3 scripts/algorithm/aruco_detector.py --camera orbbec --marker-length 0.05

# 原 RealSense 检测
python3 scripts/algorithm/aruco_detector.py --camera realsense --marker-length 0.05

# 有限帧自检，完成后关闭相机，不提供网页
python3 scripts/camera_preview.py --camera orbbec --frames 60 --no-web
```

支持原有全部 `--web-*` 和 `--no-web` 参数。
两个进程分别使用两台相机时，网页端口应不同，如 `--web-port 8081`。

| 新参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--camera` | 终端选择 | `realsense` / `orbbec` |
| `--camera-width` | 640 | 原始彩色流宽度 |
| `--camera-height` | 480 | 原始彩色流高度 |
| `--camera-fps` | 30 | 相机帧率，与网页发布帧率分开 |
| `--camera-serial` | 未指定 | 多台同类相机时指定序列号 |

标定命令将这些参数放在 `intrinsic/extrinsic` 子命令**之后**。

## 标定文件隔离

| 相机 | 默认内参 | 默认手眼 |
| --- | --- | --- |
| RealSense | `resources/calibration/camera_intrinsics.json` | `resources/calibration/hand_eye_calibration.json` |
| Gemini 305 | `resources/calibration/camera_intrinsics_orbbec_gemini305.json` | `resources/calibration/hand_eye_calibration_orbbec_gemini305.json` |

原有 RealSense 文件内容保持不变。新生成文件增加 `camera` 元数据，包含相机类型、
序列号和流配置。加载时检查类型、实际序列号和内参分辨率；错误就拒绝运行并关闭相机。
没有元数据的旧 RealSense 文件兼容读取并打印提示；Gemini 拒绝加载无相机标识的旧文件，
避免把 RealSense 的参数误用于 Gemini。相机换装后，仍须重新标定手眼：序列号相同
不能证明机械安装位置未变。

### 当前 Gemini 内参来自出厂 SDK

本次已实际导出当前 Gemini 的 640×480 彩色内参到默认 Gemini 文件，字段
`source` 为 `factory_sdk`。这是设备提供的参数，不是虚构的标定结果，
也不代表已验证实际定位精度。OpenCV 使用 8 个 rational Brown 畸变参数，
顺序为 `[k1,k2,p1,p2,k3,k4,k5,k6]`，保留 SDK 的全部径向项。

需要为另一台设备或另一分辨率导出时，用新路径（工具拒绝覆盖已有文件）：

```bash
python3 scripts/camera_preview.py --camera orbbec --frames 30 --no-web \
  --export-intrinsics /tmp/gemini305_factory_intrinsics.json

python3 scripts/algorithm/aruco_detector.py --camera orbbec \
  --intrinsics /tmp/gemini305_factory_intrinsics.json --marker-length 0.05
```

### 用 ChArUco 替换为实测内参

```bash
python3 scripts/algorithm/camera_calibration.py intrinsic --camera orbbec \
  --num-images 20 --save-images-dir resources/intrinsics_img/orbbec_gemini305
```

网页采集不同位置和倾角的标定板图像，成功后替换 Gemini 默认内参文件，
不会覆盖 RealSense 文件。使用工程当前板参数：7×5 格、格长 15 mm、
marker 边长 11 mm、`DICT_4X4_50`；必须与实际板一致。
本次没有人为摆板完成多姿态实测内参标定。

### 新相机手眼标定与后续伺服

本次没有生成 Gemini 手眼标定文件。相机的光学中心、安装位置均已变化，
不能复制 RealSense 的手眼矩阵。后续在实际安装完成后执行：

```bash
# 需要机械臂在线；由操作者调整姿态后网页采集
python3 scripts/algorithm/camera_calibration.py extrinsic --camera orbbec \
  --mode eye_in_hand --num-poses 15

# 完成 Gemini 手眼标定后才能使用；默认 dry-run，仍需要机器人在线
python3 scripts/main_pbvs.py --camera orbbec
python3 scripts/visual_servo_hover_test.py --camera orbbec --mode camera
```

独立 ArUco 默认不加载手眼、不连接机器人。需要转换到机器人坐标系时，显式传入
对应的 `--hand-eye`。PBVS 和悬停原有 `--execute` 与终端执行确认机制保留。
本次未运行机械臂运动，未验证真实闭环伺服或更换相机后的工作空间覆盖。
网页结束按钮仍走原有退出流程，执行模式下可能回位，不能当作急停。

另外，本次检查发现 Jetson 当前系统 `python3` **尚未安装 `spatialmath` 和
`roboticstoolbox` 模块**，因此 PBVS/悬停脚本目前连 `--help` 都会先遇到原有机器人依赖
缺失。相机采集、内参标定和无手眼的独立 ArUco 功能不依赖这两个模块，已经实测运行。
联动前需在机器人运行环境补齐这些原有依赖及 Fairino SDK，并用同一解释器安装
Orbbec 包；本次相机安装脚本只配置相机环境，不安装或调整机器人运动学软件栈。
